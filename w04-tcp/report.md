# W04 TCP 과제 보고서

이번 과제에서는 TCP의 신뢰성, 연결 성능, 혼잡 제어를 구현하고 측정했다.

Task 1에서는 데이터를 8바이트 단위로 나누고 바이트 오프셋을 담은 누적 ACK를 쓰는 stop-and-wait 방식을 구현했다. seed 246에서 2,000바이트를 옮기는 데 323번 전송했다. seed 999에서도 수신 데이터는 원본과 같았다. 손실은 재전송을 일으켰고 중복과 순서 변경은 결과를 바꾸지 않았다.

Task 2에서는 Wi-Fi와 휴대폰 테더링에서 각각 다섯 번 전송했다. 처리량 중앙값은 Wi-Fi 164.60 Mbps, 테더링 83.94 Mbps였으며 중앙 핸드셰이크 시간은 각각 9.3 ms와 29.7 ms였다. 두 망의 무선 상태와 경로도 달라 처리량 차이를 RTT만으로 설명할 수는 없다. RTT가 길면 TCP slow start가 윈도우를 키우는 데 더 오래 걸린다.

macOS 캡처에 관리자 암호가 필요해 공식 9판 TCP trace를 Path B로 썼다. 프레임 1–3은 SYN, SYN-ACK, ACK이며 초기 순서 번호는 클라이언트 4236649187, 서버 1068969752였다. ISN은 연결마다 새로 고르는 32비트 시작 번호다. 이전 연결의 지연 세그먼트가 새 연결과 겹칠 가능성을 낮추고 번호를 예측해 위조하는 공격도 어렵게 한다 ([RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.4), [RFC 6528](https://www.rfc-editor.org/rfc/rfc6528.html)). 서버가 프레임 143에서 알린 수신 윈도우는 1358 × 128 = 173,824바이트였으며 프레임 145에서 확인한 전송 중 데이터는 75,296바이트였다. 이 trace에는 192.168.86.68에서 gaia.cs.umass.edu로 `alice.txt`를 보내는 기록이 있지만 실제 보낸 사람의 신원까지 알 수는 없다.

Task 3에서는 slow start 뒤에 AIMD를 적용했다. 손실 때 윈도우를 0.75배로 낮춘 결과 goodput 972.8, 손실 0.5%, 평균 큐 4.9를 기록해 strong 기준을 넘었다. ACK와 손실 이벤트에서 측정한 윈도우 평균은 약 25.6패킷으로, 20패킷의 파이프와 평균 약 5패킷의 큐에 가깝다.

`python3 w04-tcp/test_tasks.py`는 7개 통과, 0개 실패했고 `python3 check.py w04`도 통과했다. 두 항목은 `tshark` 부재와 사람 채점 항목 때문에 건너뛰었다.
