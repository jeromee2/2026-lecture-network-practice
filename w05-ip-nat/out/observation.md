# 5주차 실습 관찰

## Task 1
`/31`은 지점 간 연결에서 두 주소를 모두 사용할 수 있고, `/32`는 첫 주소·마지막 주소·브로드캐스트 주소가 모두 하나의 주소로 같다.
`10.20.30.70`은 `/8`, `/16`, `/24`, `/26`과 기본 경로에 모두 해당하며, 가장 긴 접두사인 `/26` 경로가 선택된다.
접두사 길이와 네트워크가 같은 경로가 중복되면 먼저 추가한 다음 홉을 유지한다.

## Task 2
첫 연결의 사설 주소 `172.16.31.96/24`와 외부에서 확인한 주소 `163.152.233.31`을 비교하면 NAT를 적어도 한 번 거친다. 정확한 단계 수는 확인하지 못했다.
테더링에서는 두 주소가 모두 바뀌었다. `192.0.0.2/32`는 464XLAT용 주소이며, `192.0.0.1` 게이트웨이로 가는 직접 연결 경로가 따로 있다.
공식 DHCP trace의 Discover는 주소를 할당받기 전이라 출발지로 `0.0.0.0`을 쓰고, 서버를 찾기 위해 `255.255.255.255`로 브로드캐스트한다.

## Task 3
경로를 접두사 길이별 해시 테이블에 저장했다. 메모리 사용량은 경로 수에 비례한다.
조회는 경로 수와 관계없이 최대 33개의 접두사 길이를 확인하고, 가장 긴 것부터 검사해 처음 일치하는 경로에서 멈춘다.
하드웨어는 처리 시간과 메모리 사용을 예측하기 쉬운 비트 단위 구조를 쓴다. 이번 Python 측정에서는 내장 해시 테이블 방식이 더 빨랐다.
